# C# 编码规范

## 优先级

- 编辑已有文件时，跟随该文件的既有风格；与本规范冲突时以文件为准
- 例外：任务本身就是风格重构时，以本规范为目标风格，而不是跟随旧风格
- 文件无既有风格时使用以下规则；全新组件用广泛接受的通用实践
- 风格与命名统一改动一律独立提交，不夹带功能改动

## 格式

- Allman 大括号：左大括号另起一行
- 所有语句块都加大括号，单行 `if` / `for` / `foreach` 也要加
- 4 空格缩进，禁止 Tab
- 每行只写一条语句、只做一个声明
- 方法与属性定义之间至少一个空行；其余位置不出现连续空行，行内不留多余空格
- 长语句拆成多行；换行时把二元运算符留在行首
- 续行未自动缩进时缩进 4 个空格，并保持一致对齐
- 文档示例把行宽控制在 65 字符内，便于移动端阅读
- 复合条件用括号突出各子句：`if ((startX > endX) && (startX > previousX))`
- 命名空间用文件作用域声明：`namespace Foo;`
- `using` 指令（using directive）放在 `namespace` 声明之外，按字母排序，`System.*` 置顶

```csharp
if (condition)
{
    DoSomething();
}
```

## 命名

- 类型、命名空间、公共成员和方法用 PascalCasing
- 接口名以 `I` 开头，特性类型以 `Attribute` 结尾
- 枚举非标记用单数名词，标记用复数名词
- 私有实例字段与 internal 实例字段用 camelCase 加 `_` 前缀：`_workerQueue`
- 静态字段用 `s_` 前缀，线程静态字段用 `t_` 前缀：`s_workerQueue`、`t_timeSpan`
- 方法参数和局部变量用 camelCase
- 常量字段与常量局部变量用 PascalCasing，不加 `_` 前缀：`IndentSize`；interop 常量须与被调用代码的名称和值完全一致
- 名称中不出现两个连续下划线，该形式为编译器生成的标识符保留
- 名称要有意义、清晰优先于简洁；除广为人知的缩写外不用缩写
- 避免单字母名称，简单循环计数器除外
- 泛型类型参数加 `T` 前缀：`TSession`；只有一个类型参数且含义自明时可用 `T`
- 命名空间用反向域名表示法
- 主构造函数参数：record 用 PascalCasing，class / struct 用 camelCase
- 与关键字冲突时用 `@` 前缀（逐字标识符），主要用于与其他语言的互操作

## 类型与成员

- 字段能加 `readonly` 就加；构造之后仍需赋值时保持普通字段，不要为此改成属性
- 静态成员通过类名调用：`ClassName.StaticMember`，不要用派生类名限定
- 参数或局部变量与字段同名时，用 `this.` 限定字段
- 类型引用和方法调用都用语言关键字，不用 BCL 类型名：`int` / `string` / `float` / `nint` / `nuint`，`int.Parse` 而非 `Int32.Parse`
- 优先用 `int`，不用无符号整型；数据域确需无符号语义时除外
- `var` 只在右侧类型显而易见时使用，典型是字面量、`new`、显式转换；`for` 循环变量用隐式类型，`foreach` 循环变量写显式类型，元素类型不算显而易见
- 不要用变量名暗示类型：类型由声明给出，变量名表达语义
- 需要运行时类型时用 `dynamic`，不要用 `var` 代替
- LINQ 查询变量与结果序列用 `var`

```csharp
// 可以：new 让类型显而易见
var stream = new FileStream(path, FileMode.Open);

// 不行：返回类型不明显
var stream = OpenStandardInput();

// 正确：用语言关键字
int count = int.Parse(text);

// 禁止：使用 BCL 类型名
Int32 count = Int32.Parse(text);
```

## 语法与语言特性

- 优先使用当前 C# 版本的新语法，避免过时的语言构造
- 集合用集合表达式初始化：`string[] vowels = ["a", "e", "i", "o", "u"];`
- 变量类型与创建类型一致时用目标类型 `new()`：`ExampleClass item = new();`
- 对象创建用对象初始值设定项，不要创建后逐行给属性赋值
- 必须赋值的属性用 `required` 修饰，不靠构造函数强制
- 内部回调和一次性函数用 `Func<>` / `Action<>`，不新定义委托类型
- 公开 API、事件，或函数本身有业务语义时，用命名委托并加 XML 注释
- 后续不需要移除的事件处理用 lambda 定义
- 释放资源用 `using` 声明（using declaration）或 `using` 语句，不手写 try-finally 调 `Dispose`
- 比较条件用 `&&` / `||`，不用 `&` / `|`，以利用短路求值；位运算仍用 `&` / `|`
- 集合操作用 LINQ 查询或方法，提高可读性
- 以简洁明晰的方式编写代码，避免过于复杂费解的逻辑

## LINQ

- 查询变量按内容命名：位于西雅图的客户用 `seattleCustomers`
- 匿名类型的投影属性用 PascalCasing，必要时用别名
- 结果中属性名有歧义时重命名：`CustomerName`、`DistributorName`，不要都叫 `Name`
- 查询子句对齐到 `from` 子句下方
- `where` 放在其他子句之前，让后续子句作用在已筛选的数据上

## 异常处理

- 只捕获能正确处理的异常，禁止无筛选器地捕获 `System.Exception`
- 用具体的异常类型，并提供有意义的错误消息

## 异步

- I/O 密集操作用 `async` / `await`，不要同步阻塞
- 有同步上下文时（UI、旧 ASP.NET）对库代码用 `ConfigureAwait(false)`，ASP.NET Core 与控制台应用不需要

## 字符串

- 短字符串拼接用内插，且用基于表达式的形式：`$"{student.Last} Score: {student.score}"`
- 循环中大量追加用 `StringBuilder`
- 含转义字符或跨多行时优先原始字符串字面量 `"""..."""`

## 注释

- 简要说明用单行 `//`，长篇解释不要用 `/* */`
- 注释独占一行，不写在代码行末尾
- 注释以大写字母开头、句号结尾，`//` 与正文之间留一个空格
- 公共类、方法、字段用 XML 注释

## 安全

- 遵循安全编码准则，谨慎处理外部输入与敏感数据

## 编辑既有代码

- 只改任务涉及的代码，不顺手整理相邻代码的格式；风格重构任务除外
- 风格重构时按本规范统一目标范围，行为保持不变，并与功能改动分开提交
- 有外部契约的名字不改：序列化、`DataContract`、反射、ORM 映射、数据绑定、P/Invoke 结构体、已发布公共 API
